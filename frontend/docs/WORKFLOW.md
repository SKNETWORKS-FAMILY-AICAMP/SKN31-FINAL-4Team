# 협업과 변경 규칙

기준일: 2026-09-22. FEEDiT 모노레포에 적용합니다.

1. 현재 브랜치와 `git status --short`를 확인하고 해당 경로의 AGENTS.md를 읽습니다.
2. `main`에 직접 커밋하지 않고 `feat/`, `fix/`, `design/`, `docs/`, `chore/` 목적에 맞는 작업 브랜치를 사용합니다.
3. 현재 파일을 읽은 뒤 필요한 범위만 수정합니다. 사용자와 다른 작업자의 미커밋 변경을 보존합니다.
4. 변경에 맞는 빌드·테스트를 실행하고 `git diff --check`를 확인합니다. 데이터 변경은 실제 데이터 검증과 예시 기반 검증을 구분합니다.
5. `DEVELOPLOG.md`에 KST 기준 시각·이유·검증·제한을 추가합니다. 기존 기록은 고치거나 지우지 않습니다.
6. 커밋·푸시·병합·운영 배포는 사용자가 결정합니다. 변경 검토가 끝나도 요청 없이 수행하지 않습니다.

커밋 제목은 `feat:`, `fix:`, `docs:`, `chore:` 등 변경 목적을 명확히 표시합니다. PR은 문제와 최종 동작, 검증 결과, 남은 제한을 적습니다. 구현하지 않은 기능이나 실행하지 않은 테스트를 완료로 표현하지 않습니다.

폴더는 `frontend/`, `backend/`, `ChatBot/`으로 나뉩니다. 프론트 내부는 `main.js`/`main.css`가 기능별 모듈을 조합합니다. 별도 `feedit-web`·FastAPI 수집기를 현재 실행 구조로 가정하지 않습니다.

비밀값·node_modules·빌드 결과·일회성 추출 결과는 추적하지 않습니다. 샘플·모델 자산·테스트 fixture는 실제 참조와 재현 목적을 확인하기 전 삭제하지 않습니다.
